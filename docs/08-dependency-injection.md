# 08 — Dependency Injection

This document details the Dependency Injection (DI) architecture and usage in the Route E-Commerce Flutter application.

---

## 1. Overview

Dependency injection is managed via [`get_it`](https://pub.dev/packages/get_it) and [`injectable`](https://pub.dev/packages/injectable).
`get_it` serves as the service locator, while `injectable` automates registration code generation at compile time.

---

## 2. Directory Structure & Key Files

```text
lib/core/di/
├── app_module.dart           # Third-party module registrations (e.g. SharedPreferences)
├── di.dart                   # Barrel export file
├── injection.dart            # DI initialization and locator definition
└── injection.config.dart     # Auto-generated dependency graph
```

- **`lib/core/di/app_module.dart`**: Declares third-party asynchronous and factory registrations such as `@preResolve Future<SharedPreferences>`.
- **`lib/core/di/injection.dart`**: Declares `final GetIt getIt = GetIt.instance;` and `@InjectableInit() Future<void> configureDependencies()`.
- **`lib/core/di/injection.config.dart`**: Generated by `build_runner`. Initializes registrations into `getIt`.
- **`lib/core/di/di.dart`**: Re-exports `injection.dart` and `app_module.dart` for clean imports across the project.

---

## 3. Initialization

DI is initialized at application startup in `lib/main.dart` before `runApp()`:

```dart
Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await configureDependencies();
  runApp(const MyApp());
}
```

---

## 4. Registration Annotations & Scope Conventions

Per `AGENTS.md` rules:

| Annotation | Usage | Examples |
|---|---|---|
| `@injectable` | Transient instances created per resolve | Feature Cubits (`LoginCubit`, `RegisterCubit`) |
| `@lazySingleton` | Instantiated lazily on first access and preserved | Repositories, Data sources, Shared Cubits (`CartSummaryCubit`), Services, `LocaleProvider`, `AppTheme` |
| `@LazySingleton(as: ...)` | Interface-bound lazy singleton | `LightColors` bound as `AppColors` |
| `@singleton` | Eager singleton instantiated at startup | Critical infrastructure (`AppLogger`, `AppEnvironment`) |
| `@module` | Third-party classes or custom provider factories | External SDK wrappers, `Dio` instances, `AppModule` |
| `@preResolve` | Asynchronous dependencies pre-resolved during `init()` | `Future<SharedPreferences>` in `AppModule` |

### 4.1 Core Bindings

| Abstraction / Class | Implementation | Scope | File |
|---|---|---|---|
| `SharedPreferences` | `SharedPreferences.getInstance()` | `@preResolve` (async factory) | `lib/core/di/app_module.dart` |
| `LocaleProvider` | `LocaleProvider` | `@lazySingleton` | `lib/core/l10n/locale_provider.dart` |
| `AppColors` | `LightColors` | `@LazySingleton(as: AppColors)` | `lib/core/theme/app_colors.dart` |
| `AppTheme` | `AppTheme` | `@lazySingleton` | `lib/core/theme/app_theme.dart` |

### 4.2 Feature Bindings

| Abstraction / Class | Implementation | Scope | File |
|---|---|---|---|
| `SplashCubit` | `SplashCubit` | `@injectable` (factory) | `lib/features/splash/presentation/view/splash_cubit.dart` |

## 5. Code Generation

When annotations are added or modified, regenerate the dependency tree:

```bash
dart run build_runner build --delete-conflicting-outputs
```

> **Note**: Generated files (`injection.config.dart`) are committed to version control so clean checkouts compile without immediately running code generation.
